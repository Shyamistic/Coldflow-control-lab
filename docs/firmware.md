# Firmware Readiness and Commissioning

The included ESP32-S3 code is a compiled acquisition/telemetry and safety scaffold, **not field-control-ready firmware**. Firmware telemetry is `UNCOMMISSIONED_FIRMWARE` and remains separate from the application evidence classes `SIMULATED`, `REPLAY`, `LIVE_TABLETOP` and `FIELD_DATA`; the application’s public `SIMULATION` value is retained only for compatibility. Generated vectors in `firmware/include/generated/safety_vectors.hpp` freeze the firmware profile and named fail-closed outcomes; regenerate them with `node scripts/generate-safety-vectors.mjs` rather than editing the header.

No firmware result crosses the physical G0-G6 boundary. G0 hardwired protection and safe plant, G1 authority, G2 abstention, G3 tabletop effect, G4 customer acceptance, G5 field effect and G6 repeatability/transfer require human-owned physical evidence. `board.hpp` leaves all GPIOs unassigned, all eight ROM identities zero and `enableActuators=false`. No network command interface is present. No flashing or wiring was performed.

Portable safety policy differs deliberately from the software visualization: local diagnostics limited to 40% duty, 5% upward increments every 50 ms and 30-second physical approval lease. The simulated optimizer's 80% range must not be copied to hardware. Eight valid air channels are required; invalid DS18B20 readings, disconnects, 85 C sentinel, bad ROM CRC, stale data, source/context uncertainty, wetness/unobserved surfaces and missing feedback inhibit. Co-location offsets do not confer food-decision calibration. Exactly 85 C is conservatively rejected for this cold rig, not asserted impossible for every DS18B20 application.

Tasks: acquisition requests nonblocking conversions and validates stable ROM identities; safety authorizes at 50 ms nominal period; sole actuator task owns GPIO/LEDC and checks expiry every 10 ms; telemetry prints one JSON line per second outside the critical task. Queue/mutex creation failures produce no output initialization. Independent hardwired motion-energy protection, pulled-down drivers and deliberate reset remain physical requirements. Software timing, power-up pin behavior, watchdog, scheduling, current/stall and E-stop deadlines require real tests; no p99/250 ms hardware timing result is claimed.

The source, surface, wetness and feedback adapters currently remain fail-closed (`SOURCE_UNKNOWN`, unobservable, unhealthy). Merely assigning GPIOs or enabling the flag cannot unlock motion. Add and validate real adapters under qualified commissioning before a local diagnostic lease can authorize any driver. No stub must be changed to unconditional true to make a demonstration move. The servo/vane, NTC index, INA219, BME280, microSD recorder and industrial interfaces are not yet wired into this scaffold; implement only after verified hardware allocation and safe experimental scope. Source unknown must not be replaced with a fabricated source-normal signal.

## Human commissioning checklist

Confirm exact S3 board/flash variant and pin conflicts; enumerate eight ROMs into labeled zone/supply/return positions; document offsets/reference uncertainty/lag; guard fans/vane and restrict currents; implement and test independent master removal/interlocks/manual reset; validate genuine source states and recovery; implement relevant surface/dewpoint/wet/drain and actuator-current/tach observations; test unplugged/stuck/invalid/stale sensors and jams; record raw data/calibration/configuration version; measure worst-case scheduled timing, brownout/reboot and driver fail-off; independently review every interlock and lease. No real-room food control until site-specific qualified approval and evidence gates.

Remote signed leases, MQTT ingestion, OTA rollback, model promotion, standard PLC/Modbus/BACnet/OPC UA are deliberately **unimplemented**, not mocked integrations. The protocol document describes gated contracts. A standard MCU/PLC is not safety equipment and no food-release authority exists.
